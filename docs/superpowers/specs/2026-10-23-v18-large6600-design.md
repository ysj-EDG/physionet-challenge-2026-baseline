# Matcha V18 Large6600 Reproduction Design

## Goal

Reproduce the public `v18-final` Matcha pipeline on the Large 6600 training
cohort while preserving the upstream model, loss, sampling, labels, feature
definitions, evaluation protocol, and deployment interface.

## Fixed scope

- Source commit: `7f2eae2fe4f170c87a21943b24ea4e217eabf67f` (`v18-final`).
- Source data is read-only from `/database2/physionet2026_kaggle/data2`.
- Formal Large6600 caches are written only below
  `/database2/physionet2026_kaggle/matcha_cache/v18_large6600`.
- Scripts, logs, reports, checkpoints, and source changes live below
  `/database/home/gaohaojie/workspace/repd/Matcha`; no scripts or reports are
  written under `/database2`.
- The local branch is `reproduction/v18-large6600`.
- Every encoder training/export job is launched and monitored in its own
  `tmux` session.
- No new model or evaluation logic is introduced. Existing repository
  entrypoints are called directly wherever possible.

## Execution layout

`artifacts/v18_large6600/` contains `encoder/`, `loso/`, `final_model/`,
`smoke/`, `scratch/`, `logs/`, and `reports/`. Formal prepared caches and
frozen embeddings are persistent inputs under
`/database2/physionet2026_kaggle/matcha_cache/v18_large6600/`; the frozen
embedding directory is immutable after successful export and is never
regenerated by downstream training.

The full pipeline orchestrator is not used as one opaque call because its
default cleanup removes the temporary workspace. Instead, its existing
preparation, encoder, export, LOSO, final-model, residual, and runtime
functions/entrypoints are executed as separate stages with explicit paths.

## Minimal allowed source change

`export_full_embeddings.py` may be changed only so an existing shard is
skipped when, and only when, its HDF5 checkpoint fingerprint matches the
requested checkpoint and its sidecar is present. A mismatched shard must be
recomputed or rejected; embeddings from different encoders must never mix.
No algorithm, feature, label, loss, sampler, model, or scoring behavior is
changed.

## Verification and recovery

Each stage writes command lines, tmux session names, exit status, and output
paths under `artifacts/v18_large6600/logs`. Completion is determined from
the upstream success markers plus manifest/checkpoint fingerprints. Existing
successful stages are reused; interrupted stages resume only through the
upstream checkpoint or shard mechanisms. Smoke artifacts remain isolated from
the formal run.

If the unmodified upstream LOSO entrypoint requires historical baseline JSON
that is unavailable, no fake baseline is created. The existing repository
LOSO implementation is used through its available direct entrypoint or
callable functions, and any unavoidable protocol limitation is recorded in
the report.

## Deliverables

The run produces environment and source metadata, prepared manifests,
encoder checkpoints, the permanent EMA-teacher embedding cache, LOSO split
and prediction files, final deployment artifacts, official-interface smoke
verification, and `reports/REPRODUCTION_REPORT.md` with actual results and
verified rerun commands.
