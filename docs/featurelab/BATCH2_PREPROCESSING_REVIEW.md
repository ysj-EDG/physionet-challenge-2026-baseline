## Key cross-cutting differences

- Position compression: ID565 concatenates separated stage epochs before spectral, complexity, and temporal statistics. FeatureLab policy retains the original grid. The candidate semantics therefore cannot be copied verbatim; per-stage windows must be redefined.
- Band-edge mismatch: four of five spectral band edges differ between the local extractor and ID565, and the local NPZ stores log-ratio columns rather than absolute band power, so the candidate cannot be reproduced from stored values.
- Budget grounding: for four of six families (ECG fragmentation 20, CAISR intervals 9, respiration complexity 24, SpO2 20) the proposed column decomposition has no corresponding implementation in ID565 or locally; for EEG spectral 288 it duplicates the implemented Batch 1 layout; for EEG complexity 192 it is only implied by the arithmetic 6 x 4 x 8. The 553 budget is audit scope, not an implementation target.
- Resampling without anti-alias filtering appears in the ID565 complexity path (100 Hz) and its YASA paths (128 Hz); local resampling uses resample_poly or FFT-based resampling.

## Risk register and approval questions

- R1 EEG spectral: stored NPZ cannot reproduce candidate band edges; an EDF recompute branch would be needed. Risk of silent semantic drift if Band 2 reuses stored columns under different band definitions.
- R2 EEG spectral overlap: the 288 layout equals the implemented Batch 1 eeg_tail family; approving Band 2 spectral as specified risks duplicating 288 existing columns with different preprocessing provenance.
- R3 EEG complexity: ID565 concatenates separated stage epochs and resamples without anti-alias filtering; both conflict with FeatureLab position-preserving policy and with local signal-quality practice.
- R4 ECG fragmentation: no fragmentation definition exists in ID565 or locally; the 20 columns cannot be derived without an approved external definition.
- R5 CAISR intervals: local static interval features use a different event model and codes than ID565; ID565 itself has no inter-event interval rules; the 9-column layout is unmapped.
- R6 Respiration complexity: no definition exists in ID565 or locally; the 24 columns cannot be derived without an approved external definition.
- R7 SpO2: only three ID565 features exist (min, pct_below88, ODI); the 20-column decomposition is unmapped, and ODI lacks nadir, duration, recovery, and minimum-gap rules; the local pipeline never reads SpO2.
- R8 Budget integrity: implementing features to fill the 553-column budget without approved definitions would fabricate formulas, which this audit forbids.

Approval questions:

- Q1 Which band edges are approved for a future EEG spectral family: local, ID565, or a third definition?
- Q2 Does the position-preserving policy forbid the ID565 concatenation, and if so, what per-stage segment lengths replace it?
- Q3 Who supplies the external definitions for ECG fragmentation and respiration complexity?
- Q4 Which CAISR event types and interval statistics define the 9-column family?
- Q5 Which SpO2 thresholds (88 vs 90), ODI baseline window, and additional features define the 20-column family?
- Q6 Confirm Batch 2 remains audit-only until these definitions are approved.

## Intermediate-cache recommendations

None of these are implemented by this audit; each would live under the private cache root and would only be built after the corresponding definitions are approved.

- EEG: per-epoch per-lead band powers at the approved band edges; per-epoch 100 Hz anti-aliased segments for complexity measures.
- ECG: per-record NN/RR interval series as the shared input for any approved fragmentation definition.
- CAISR: per-record event tables (type, onset, offset) per annotation channel, aligned with the existing run-length segmentation code.
- Respiration: 25 Hz filtered envelope per channel, saving recompute of the existing bandpass and Hilbert stages.
- SpO2: per-record desaturation event table plus per-epoch aggregates, both derivable from a single channel pass at native rate.
